# ARM64 iOS compatibility

This branch develops a target-neutral ARM64/iOS compatibility foundation for ipaSim on Windows. Public validation uses only synthetic fixtures generated by this repository; private application binaries are not required for contributors to reproduce or fix emulator behavior.

## Implemented foundation

- AArch64 Unicorn guest execution replaces the hard-coded 32-bit ARM engine.
- Guest register values are 64-bit.
- AAPCS64 integer and pointer argument flow uses X0-X7.
- X30 is used as the link register.
- Guest SP is 16-byte aligned.
- Mach-O fat binaries explicitly select an ARM64 slice instead of slice 0.
- Missing ARM64 slices fail explicitly.
- Mach-O segment and section parsing uses the 64-bit structures.
- Modern chained fixup and exports-trie handling is implemented in the ARM64 loader path.
- Classic dyld relocation and binding targets are pointer-width.
- The Objective-C class-data pointer mask no longer truncates ARM64 addresses.
- The Windows build environment starts an x64 developer toolchain.
- The primary ipaSim build targets are `ipaSim-x64-Debug` and `ipaSim-x64-Release`.
- LIEF and libffi are built as x64 runtime dependencies.
- The x64 emulator core no longer depends on Win32-only WinObjC or ANGLE binaries.
- A 32-bit host is rejected explicitly before an ARM64 Mach-O is mapped.
- Windows-backed Darwin compatibility services are added only where semantics can be defended.
- Unsupported runtime behavior fails explicitly rather than being represented as success.

## Public validation order

1. Run **Synthetic iOS IPA on Windows** (`.github/workflows/synthetic-hello-ipa.yml`).
2. Require the bootstrap synthetic IPA to execute its real ARM64 Mach-O entry point through ipaSim on Windows and return guest `X0=42`.
3. Inspect the untouched minimal IPA and UIKit Hello World probes for the next clean compatibility boundaries.
4. Run **Windows ARM64 Core** (`.github/workflows/windows-arm64-core.yml`) and require its semantic/core tests to pass.
5. Only after the public checks pass, optionally perform private local acceptance with the generic `ipasim-ipa-tester` artifact.

Public bug reports should use the repository synthetic fixtures and their logs. Do not upload or identify private application IPAs, bundle names, paths, RuntimeRoot contents, screenshots, or private application logs.

## Synthetic fixtures

The synthetic workflow builds three iOS IPAs on a GitHub macOS/Xcode runner:

- `HelloBootstrap.ipa`: minimal ARM64 entry point returning 42; CI proves it has zero undefined guest symbols before redirecting Apple's otherwise-unused mandatory `libSystem` load command to the existing ipaSim host bridge. Windows execution must report `X0=42`.
- `HelloNative.ipa`: untouched minimal iOS executable used to expose the real native runtime dependency boundary.
- `HelloUIKit.ipa`: small Objective-C UIKit Hello World application used to expose framework/runtime boundaries after the low-level execution path works.

## Generic local tester

The `Windows ARM64 Core` workflow publishes `ipasim-ipa-tester` containing `Test-Ipa.cmd` and `Test-Ipa.ps1`. The tester auto-detects the top-level `.app` and Mach-O executable instead of encoding an application name.

A local private acceptance command is:

```text
Test-Ipa.cmd "C:\path\to\App.ipa"
```

Optionally, an owner can provide an extracted runtime root locally:

```text
Test-Ipa.cmd "C:\path\to\App.ipa" "C:\path\to\RuntimeRoot"
```

ipaSim does not package or download Apple runtime binaries.

## Compatibility rule

No missing framework, loader, ABI, filesystem, process, socket, or Mach behavior should be silently ignored. Unsupported functionality must produce a named diagnostic until a defensible implementation replaces it. No runtime method swapping or monkey patching is used.
